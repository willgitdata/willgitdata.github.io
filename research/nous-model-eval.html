A metric others can adopt: MQD

MQDi = ( Qi − Qref ) / ( Ci − Cref )

Marginal Quality per Dollar. Leaderboards publish "quality per dollar" (Q/C), which is dominated by whichever model happens to be cheapest and rewards cheap failure. MQD asks the question a buyer actually asks — what does the next dollar buy? — by measuring the quality gain per extra dollar spent over a value reference ref: the cheapest model in the top half of the ranked field, i.e. a baseline that is already good. Positive MQD means the premium pays for itself; a premium model with lower quality than the reference gets a negative MQD and is dominated outright.

Reference here: particle-1 (cheapest model scoring at or above the field median) (Q=8.90, C=$0.0137). Computed per item: kimi-k3.1-pro +2.70, gpt-6.1-terra-pro +1.74, glm-5.3-flashx-legal -13.36 points per extra dollar.

What a task looks like

Every model gets the same prompt, a fixed output budget, and no tools — that is exactly what Compare panes stream. Here is one of the executable items in full:

You are working in a Python service repo. Fix the ROOT CAUSE of this bug; four other modules call `Pool.checkout()`, so caller-side patches are wrong. Return ONLY the complete corrected `Pool` class in one ```python block, keeping the same public API (`Pool(factory, size)`, `checkout()`, `checkin(conn)`). Max 70 lines. No prose after the code.

BUG: under 40 threads the service intermittently raises `RuntimeError: Set changed size during iteration` and sometimes hands the SAME connection to two workers, corrupting protocol state.

```python
import threading

class Pool:
    def __init__(self, factory, size=8):
        self._factory = factory
        self._idle = set()
        self._all = set()
        self._lock = threading.Lock()
        self._size = size

    def checkout(self):
        for conn in self._idle:
            self._idle.discard(conn)
            if conn.is_healthy():
                return conn
        if len(self._all) < self._size:
            conn = self._factory()
            self._all.add(conn)
            return conn
        return None

    def checkin(self, conn):
        if conn.is_healthy():
            self._idle.add(conn)
        else:
            self._all.discard(conn)
            conn.close()
```

The returned Pool is then executed against a hidden harness: 40 threads × 150 checkout/checkin cycles, a guard that raises on any connection handed to two threads at once, a check that the pool never creates more than size connections, and a dead-connection recycling check. No human opinion is involved in that score.

Method, and what changed from a single-judge comparison

  • Variance. Every item is one sample at the model's default sampling, so per-item noise is not measured directly. What is reported here is dispersion across the battery: independent tasks and a judged-task spread of ±2.1 points between models. Treat the ranking as a battery-level result, not a confidence interval on a single prompt.
  • Execution, not vibes. Every task whose answer is runnable is scored by running it against hidden tests locally — same harness, same seeds, no judge (the concurrency, parser and SQL items). The remaining tasks are the ones where no cheap oracle exists, and those are the judged ones.
  • Blinding. Judged items were re-labelled with random two-character codes and shuffled per task before scoring, so the judge never saw a model name; the code→model mapping was sealed until every score was written. One judge scored this sweep, so inter-rater agreement is not measured — a second independent judge is the next thing to add, and the harness is set up for it (two or more judges are averaged automatically).
  • Reasoning you pay for but never see. Bills include hidden reasoning tokens. Rather than hide that, it is published as reasoning overhead above, and the quality-per-dollar column uses the full billed cost.
  • Billing hygiene. Every pane ran under a hard spend cap enforced by the harness, which sums provider-reported cost after each request and stops the sweep when the cap is reached. The cap did not save this run: the provider bills against a shared account balance, so ~0.49 USD of requests exhausted it before the cap bound, and the last third of the matrix failed the credit check. Those cells are flagged, not silently dropped — which is why the coverage column exists.

Limits that remain

  • One sample per item: no test–retest reliability per prompt. Adding a second sample per item roughly doubles cost and is the single most useful next step.
  • Compare panes run with tools stripped, so this measures answer quality under Compare's contract, not full agent-loop behaviour (file edits, multi-step tool use, test loops). The executed-test tasks partly compensate.
  • Both judges are the same model family, so inter-judge agreement measures rubric stability, not cross-vendor agreement. A third judge from a different vendor would be the honest fix.
  • Single-turn, single language pair per task family; a Godot task judged from source only is not a Godot task compiled in an engine.
  • Two of the ten newest model IDs in the catalogue were not reachable on this account (one returned 400, one 403), so the next-newest accessible IDs were used. The set is "newest usable", not "newest listed".
