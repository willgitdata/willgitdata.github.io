From an empty directory to an agent that remembers something, recalls it, and shows you why it chose what it did. Roughly fifteen minutes, most of it waiting on installs.

This page is the long version, and it names the things the short version leaves out: which keys you actually need, which you don't, and what each moving part is doing with your data. If you just want the code, the Quickstart is four steps.

What you need first

Two things, and one of them you probably already have.

ThingNeeded?Why
Node 20+ Yes Runs the gateway, console, and site. node --version to check.
pnpm Yes This is a pnpm workspace. npm cannot install it — it does not implement the workspace: protocol the packages use. Node 20+ ships pnpm: corepack enable.
An OpenAI or
Anthropic key		 Yes Yours, for your own agent. Apoideia wraps the LLM client you already use; it never proxies your model calls or holds your model credential. The key stays in your process and goes straight to your provider.
Postgres No The boot script finds one or provisions a private cluster for you.
An AWS account No Locally, an S3-compatible stub runs in-process. You only need real object storage in production — see what is actually running.
Docker No Used if present, not required. There is a docker-compose.yml if you prefer it.
An Apoideia
model key		 No There isn't one. Apoideia itself makes no LLM calls — see the learning loop is not a model call.

The steps

  1. Boot the stack

    git clone <repo> && cd apoideia
corepack enable        # skip if you already have pnpm
pnpm dev

    One command, and it does its own setup: generates the secrets it needs into .env, finds or provisions a Postgres, installs the workspace, builds the console, and starts everything.

    First boot takes a few minutes — a Python environment for the memory plane and a console build. Later boots are seconds. When it is ready it prints:

    [up] all services up
       gateway  http://localhost:4000
       console  http://localhost:5173
       site     http://localhost:4321
    If it refuses to start saying a port is held by something it did not start, that is deliberate — booting anyway would leave you talking to an older process with older secrets, which surfaces later as an unrelated-looking 401. It prints the exact command to clear it.

    Use pnpm down to stop everything, including a database it provisioned for you.

  2. Create your account

    Open the console and choose Create an account. Email and a password of at least 8 characters — that is the whole signup. You land straight in the Fleet area.

    On a local stack there is no confirmation email and no password reset: the gateway holds the password itself, and it has no mail sender. If you lose the password, whoever runs the gateway resets it. A deployment wired to a hosted identity provider gets both.

  3. Mint an API key

    Developer → API keys → New key. It starts with apo_live_ and is shown once — the gateway stores only a hash, so a lost key is minted again, never recovered.

    export APOIDEIA_API_KEY=apo_live_...
export APOIDEIA_BASE_URL=http://localhost:4000

    APOIDEIA_BASE_URL is the only self-host/cloud seam in the SDK. Point it at your own gateway and nothing else changes.

  4. Install the SDK

    pip install -e "sdks/python[anthropic]"   # or [openai]
# TypeScript: npm install ./sdks/typescript

    The extra pulls in the provider client you already use. If you have one installed, plain pip install -e sdks/python is enough.

  5. Wrap the client you already have

    This is the whole integration. You keep writing the same provider calls; agent.wrap() adds recall, injection, and tracing around them.

    from apoideia import Apoideia
from openai import OpenAI

apo = Apoideia()
agent = apo.agent("claims-triage")
client = agent.wrap(OpenAI())

with agent.run() as run:
    resp = client.chat.completions.create(
        model="gpt-5-mini",
        messages=[{"role": "user", "content": "Triage claim #4821..."}],
    )
    run.finish(outcome="success")

agent.remember("Adjuster Diaz handles roof claims above $15k.")
hits = agent.recall("who handles large roof claims?")
print(hits.results[0]["content"], hits.trace.strategy)

    apo.agent("claims-triage") creates the agent the first time it is called — you do not have to make one in the console first. The slug is the identity; reuse it and you reuse the agent.

    Your model key never reaches Apoideia. wrap() returns your own client with the same methods. The provider call is still made by your process, with your credential, direct to your provider. Apoideia sees the messages it injects memory into and the trace it records — not your API key.

  6. Watch it happen

    Back in the console, Fleet → Agents → claims-triage. Six tabs:

    • Overview — spend this month against the agent's resolved budget, and every configuration key with the scope that decided it.
    • Runs — one row per agent.run(), with its outcome.
    • Recall — run a query by hand and read the trace: which strategy answered, what it considered, why those results.
    • Memories — what the agent knows, added by hand or by remember().
    • Skill log — lessons the learning loop distilled, and whether each is active.
    • Configuration — this agent's overrides.

What is actually running under that

Four processes and two stores. Worth knowing before you deploy, because two of them hold your data.

PieceHoldsIn production
Postgres Orgs, users, agents, API key hashes, runs, lessons, audit log, quota counters. Any Postgres. Set DATABASE_URL; migrations run on gateway start.
Object storage The memories themselves. One state blob per agent, at state/org_<id>__agent_<id>, written with an ETag compare-and-swap so two concurrent writers cannot silently clobber each other. Real S3, or anything S3-compatible — MinIO, R2, Ceph. Set S3_ENDPOINT_URL, S3_BUCKET_NAME and AWS credentials.
Gateway Nothing. Serves the API, holds sessions in Postgres. Node service. Needs APOIDEIA_MEMORY_KEY, APOIDEIA_RETRIEVAL_KEY, INTERNAL_SERVICE_TOKEN.
Distiller Nothing. Reads runs, writes lessons. Same image as the gateway, its own process, so it restarts independently.

Yes, object storage is on the hot path. Every remember(), recall() and forget() reads and writes that blob. Locally an S3-compatible stub serves it out of .data/fake-s3/, so you need no AWS account to develop — but you do need a real bucket before anyone else depends on it, and it is the thing to back up.

The learning loop is not a model call

The distiller groups failed runs by a normalised error signature and promotes a lesson when a pattern repeats. That is ordinary code — no model, no key, no per-lesson inference bill, and no third party receiving your run data. It is also why lessons are cheap enough to run continuously and legible enough to audit: you can read exactly why one exists.

The only place Apoideia wants a model key of its own is the evaluation harness, which reproduces the published benchmark numbers against a real model. That is opt-in and unrelated to running the product.

Running a fleet day to day

Most teams never create an agent by hand. The pattern that scales:

  • Agents appear from code. One slug per workload — claims-triage, contract-review. First call creates it; the console fills in as your code ships.
  • Set policy once, at the org. Fleet → Configurations holds the defaults every agent inherits: how many lessons may be injected, the injection token ceiling, monthly budget, whether lessons need review before going active.
  • Override only the exceptions. An agent that sets a key overrides the org for that key alone. The Overview tab labels every value set on this agent or product default, so you always know what a number means before you change it — and clearing an override returns it to inheriting.
  • Budgets are enforced, not advisory. A write past the limit gets a 402 from the gateway.
  • Pause beats delete. Pausing stops an agent taking work while keeping its memories and lessons. Export first if you mean it — delete is permanent.

Putting it in front of other people

The local stack is a real stack, not a mock — same code, same schema. Three things change when other people use it.

Keep the console and the gateway on one registrable domain. The session cookie is SameSite=Lax and the console calls the gateway with credentials. console.example.com with api.example.com works, because those are the same site. A console on one vendor's domain and a gateway on another's is cross-site: the browser withholds the cookie and nobody stays signed in. This is the single most common way a working stack breaks on deploy.

Then set the origins so each part knows where the others are — CONSOLE_ORIGIN and SITE_ORIGIN on the gateway (they are also its CORS allowlist), and GATEWAY_ORIGIN on the site and console. Point APOIDEIA_MEMORY_URL at the memory plane, give the bucket real credentials, and keep the three generated secrets out of source control — .env is gitignored for that reason.

Signup is open. Anyone who can reach the console can create an account and an org. There is no invite list, allowlist or billing gate in this version — put it behind your own perimeter until you add one.
