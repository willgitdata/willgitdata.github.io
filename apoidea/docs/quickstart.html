Quickstart

Apoideia wraps your existing LLM client with durable memory, an explainable recall trace, and an automatic learning loop. No new framework to learn — you keep writing OpenAI/Anthropic calls the way you already do.

1. Get a gateway

You need a running Apoideia gateway and its URL before anything below will do anything. Two ways to get one:

  • Already have one (your own deploy, or one a teammate runs) — skip ahead, you just need its URL and an API key from its console.
  • Don't have one yet — clone this repo and boot a local stack: 
    git clone <repo> && cd apoideia
pnpm demo
    Boots Postgres, the memory plane, the gateway API, this site, and the console on localhost; seeds a demo org; runs the scripted claims-triage learning arc. Prints your console URL and login when ready.

2. Install the SDK

pip install -e "sdks/python[anthropic]"   # or [openai], depending on your client
# TypeScript: npm install ./sdks/typescript

3. Create an account and an API key

Open the console's sign-in page — http://localhost:5173/auth on a local stack, wherever yours is deployed otherwise — and sign up with an email address and a password.

Email is the only sign-in method in v0.1. GitHub and Google are deliberately not in this release: neither is registered, and the console renders its provider buttons from a list the gateway serves, so adding one later is configuration rather than a rewrite. There is nothing else to click on the sign-in page.

Then open the Developer area and create a key under API keys:

  • The key is shown once. Only a salted SHA-256 hash of it is stored, so nobody — us included — can display it again; a lost key is revoked and replaced, not recovered.
  • It starts with apo_live_. The first few characters are kept in the clear as a lookup prefix, which is what the console shows you in the key list afterwards.
export APOIDEIA_API_KEY=apo_live_...
export APOIDEIA_BASE_URL=http://localhost:4000   # your gateway's URL — the only self-host/cloud seam

4. Wrap your agent

from apoideia import Apoideia
from openai import OpenAI

apo = Apoideia()
agent = apo.agent("claims-triage")
client = agent.wrap(OpenAI())

with agent.run() as run:
    resp = client.chat.completions.create(
        model="gpt-5-mini",
        messages=[{"role": "user", "content": "Triage claim #4821..."}],
    )
    run.finish(outcome="success")

agent.remember("Adjuster Diaz handles roof claims above $15k.")
hits = agent.recall("who handles large roof claims?")
print(hits.results[0]["content"], hits.trace.strategy)

Every wrapped call injects the run's recalled memory and active lessons into the system prompt (capped by the SDK at APOIDEIA_INJECT_MAX_TOKENS, default 1500, estimated at 4 characters per token) and posts a trace event with token usage.

Recall failures never break your call — they fail soft, and the call proceeds with no injected context. The Python SDK records why on the apoideia logger at DEBUG, so an unreachable memory plane and a genuinely empty recall are distinguishable in your logs rather than identical:

logging.getLogger("apoideia").setLevel(logging.DEBUG)

The TypeScript SDK currently swallows the same failure without logging it. That is a gap, not a design decision — treat an unexplained absence of injected context there as worth checking against the gateway.

One recall per run, not per call. The query is the first user message of the run — the task you opened it with — because a run is one unit of work and the last message in a loop is usually a tool result, not what the agent is actually working on. Every later call in the run reuses that recall, so a ten-step agent loop pays for one. Want to ask memory something else mid-run? Call agent.recall() directly with your own query.

5. Watch it learn

The distiller mines finished runs for repeated errors (pitfalls), winning tool sequences (playbooks), and explicitly promoted notes (facts). Lessons are scored from the outcomes of runs they were injected into, and muted automatically if they stop helping. Check the Skill Log in the console on any agent's detail page.
